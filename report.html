Project Overview

What we built

A full-stack Visual Question Answering system featuring a fine-tuned PaliGemma-3B model with LoRA adapters, capable of answering multi-turn questions about images in natural language — deployed as a production-ready web application.

Problem Statement

Visual Question Answering (VQA) requires a model to jointly understand image content and natural language questions. Extending this to multi-turn dialogue — where follow-up questions reference prior context — adds significant complexity.

Standard VQA models (e.g., BLIP) treat each question independently, failing to leverage conversational history. We address this by fine-tuning a large vision-language model (VLM) on multi-turn conversation data.

Research Questions

  • Can LoRA fine-tuning adapt a 3B VLM for multi-turn VQA on limited compute?
  • How does conversation history length affect answer quality?
  • What engineering challenges arise when deploying VLMs on consumer hardware?

Key Contributions

1. Efficient Fine-tuning

float16 LoRA fine-tuning of PaliGemma-3B on a single T4 GPU — only 0.56% of parameters trained, reducing memory from ~12 GB to ~7 GB.

2. Multi-Turn Conversation

Trained on LLaVA-Instruct conversation format, enabling the model to use prior Q&A context in follow-up answers.

3. Full-Stack Deployment

Deployed as a web app (FastAPI + React) with 4-bit inference, GradCAM attention visualization, and model comparison UI.

4. Engineering Solutions

Solved 6 cascading GPU/library issues on Kaggle: bitsandbytes CUDA kernels, DataParallel OOM, numpy ABI mismatch, FP16 gradient errors.

Why LoRA?

LoRA freezes the base model and adds small rank-decomposition matrices to attention layers. This reduces trainable parameters from 3.2B → 18.1M (0.56%), enabling fine-tuning on a single 16 GB GPU.

Multi-Turn Prompt Format

Input format (matching LLaVA-Instruct)
Q: What is in this image? A: A cat sitting on a mat. Q: What color is it? A:

The model sees the full conversation history. Each Q-A pair is concatenated. Only the final answer tokens are used for loss computation (label masking via suffix parameter).

Ablation Study & Qualitative Results

Ablation: Conversation History Length

We evaluated how much prior conversation context helps the model answer follow-up questions. Exact Match is 0% for all settings (metric limitation), but qualitative analysis shows longer history produces more coherent contextual answers.

Figure 2: Conversation history length ablation (Exact Match metric). 0% reflects metric unsuitability for open-ended generation — not model failure.

Metric Limitation

Exact Match requires character-for-character equality. VQA v2 uses this for single-word answers ("yes/no/2"). For descriptive multi-sentence answers like ours, BLEU-4 or BERTScore would show real differences. This is a known limitation we'd address in future work.

Inference Optimizations

  • 4-bit NF4 quantization (bitsandbytes) — fits 3B model in 1.5 GB VRAM on RTX 3050 4 GB
  • Lazy loading — backend starts immediately; PaliGemma loads in background thread on first request
  • HF model cache — base model downloaded once (~3 GB), cached locally
  • Beam search (num_beams=3) — better answer quality vs greedy decoding

Engineering Challenges Solved

1. DataParallel OOM

Kaggle T4 nodes expose 2 GPUs to device_count() → Accelerate uses DataParallel → 64 MB gradient buffer → OOM. Fix: CUDA_VISIBLE_DEVICES=0 before torch import.

2. bitsandbytes CUDA Error

PEFT imports bitsandbytes → broken CUDA kernels on T4. Fix: sys.modules['bitsandbytes'] = None before imports, making find_spec() return None.

3. FP16 Gradient Error

GradScaler requires float32 gradients; LoRA initialized in float16. Fix: use autocast_adapter_dtype=True (PEFT default) to cast adapters to float32.

4. Numpy ABI Mismatch

TF import triggers scipy → numpy ABI clash. Fix: TRANSFORMERS_NO_TF=1 env var + reinstall numpy==2.0.2 last.

Conclusion & Future Work

Summary

We successfully fine-tuned PaliGemma-3B with LoRA on multi-turn visual conversations, trained in 1h 15min on a free Kaggle T4 GPU, and deployed as a full-stack web application supporting 5 VQA modes including our custom fine-tuned model running locally at 4-bit precision.

What Worked

  • LoRA reduces trainable params to 0.56% — feasible on T4
  • Train loss dropped 54% (2.4 → 1.1) — real learning signal
  • Multi-turn demo shows coherent contextual reasoning
  • 4-bit inference fits 3B model in RTX 3050 4 GB
  • Full-stack deployment works end-to-end

Limitations

  • Only 1,800 training samples (budget/time constraint)
  • Val loss plateau — mild overfitting
  • Exact Match metric wrong for descriptive answers
  • First inference ~10–30s (model warm-up)
  • No BLEU/CIDEr/BERTScore evaluation

Future Work

  • Train on full 150K samples for 5+ epochs
  • Implement BLEU-4, CIDEr, BERTScore metrics
  • Compare with instruction-tuned paligemma-3b-it
  • Add QLoRA (4-bit training) for larger batches
  • Attention visualization for PaliGemma
